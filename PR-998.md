# PR #998: Fix Duplicate Route Mounts

## Summary of the Issue

The `backend/src/server.js` file had duplicate route mounts for `accountRoutes` and `paymentRoutes`. These routes were incorrectly mounted twice:
1. **First mount**: Before the rate limiter middleware (lines 67-68)
2. **Second mount**: After the rate limiter middleware (lines 84-85)

This configuration caused every request to `/api/accounts` and `/api/payments` endpoints to hit the route handlers twice, leading to:
- Redundant processing overhead
- Potential double-execution of business logic
- Inconsistent behavior and unpredictable side effects
- Possible data integrity issues if handlers perform mutations

## What Was Changed

Removed the first pair of duplicate route mounts (lines 67-68) that appeared before the rate limiter middleware.

The routes are now correctly mounted only once, after the rate limiter, ensuring:
- All account and payment API requests are properly rate-limited
- Route handlers execute exactly once per request
- Consistent middleware application order

**Files modified:**
- `backend/src/server.js` - Removed duplicate `app.use()` calls for account and payment routes
